# Задача для Морфа, фаза 1: компонент `evm` (анализ байткода)

> Дата: 28.09.2026. Проект ETHSmartChecker, план — `plan.md` §5, фаза 1.
> Запись системы — `contour.yaml`, компонент `evm`: пять Function с examples.
> Фикстуры — `tests/fixtures/`, их опись и источники — `tests/fixtures/README.md`.
> Разбивки на карты здесь нет.

## 1. Зачем это

Все остальные компоненты пруфа (fingerprint, store, cluster, ingest, cli) работают
над результатами `evm`. Без `evm` в проекте нет ни одной строки кода, `pytest`
сообщает `no tests ran`.

Что показал реальный блок 26077729 (`tests/fixtures/codes_26077729.json`):
- 206 адресов-кандидатов, из них 147 с кодом и 130 разных кодов;
- 8 из 147 — клоны EIP-1167, 12 — EOA с делегированием EIP-7702 (`ef0100` + адрес);
- 8 пулов Uniswap V3 и 5 токенов LaunchToken отличаются только immutables в
  PUSH32: побайтовое сравнение считает их 13 разными кодами, а скелет — двумя
  семействами.

L0, L1 и proxy-кластеры фазы 3 опираются на пять функций этого компонента, а
L2-похожесть — на селекторы. Ошибка на этом уровне молча исказит все кластеры.

## 2. Контракт

### 2.1. Формы ВХОДНЫХ данных

| форма | где определена | как построить в тесте |
|---|---|---|
| Runtime Code, `bytes` | `contour.yaml`, Data Object `Runtime Code` | `bytes.fromhex(open(p).read().strip()[2:])` для `p` из `tests/fixtures/code_*.hex`. Файл — строка `result` ответа `eth_getCode` дословно: `0x` + hex, без перевода строки |
| синтетические байты | examples в `contour.yaml` | `bytes.fromhex("600161ff")`, `b""`, срез фикстуры (`code[:44]`), копия с одним изменённым байтом (`bytearray`) |

Других входов нет: модуль не читает файлы, окружение и сеть.

### 2.2. Формы ВЫХОДНЫХ данных

- `disassemble` → `list` кортежей `(pc: int, op: int, arg: bytes)`. Именно `tuple`, не
  `list` и не namedtuple-подкласс со своим `__eq__`.
- `strip_metadata` → `tuple` `(body: bytes, trailer: bytes)`.
- `extract_selectors` → отсортированный `list` из `str` вида `"0x" + 8 hex`, строчные буквы.
- `detect_proxy` → `dict` ровно с ключами `"kind"` и `"target"`, или `None`.
  `target` — `"0x"` + 40 строчных hex.
- `build_skeleton` → `bytes`, длина равна длине `body`.

### 2.3. Имена

- Модуль `ethsc/evm.py`. Функции: `disassemble`, `strip_metadata`,
  `extract_selectors`, `detect_proxy`, `build_skeleton`.
- Значения `kind`: `"eip1167"`, `"eip7702"`.
- Тест кодовой карты — `tests/test_evm.py`, тест судьи — `tests/test_evm_examples.py`.
- Поведение каждой функции — дословно `behavior` из `contour.yaml`. Числа — из
  `examples`: они проверены по фикстурам и независимым источникам.

### 2.4. Что не должно сломаться

`ethsc/__init__.py` остаётся пустым. `contour.yaml`, `plan.md`, `tests/fixtures/*`
не трогаются.

## 3. Приёмка

Базовая линия: 0 тестов (`no tests ran`).

1. **Кодовая карта** (`ethsc/evm.py` + `tests/test_evm.py`), ступени от узкой к широкой:
   1. `ast.parse(..., feature_version=(3,9))` по обоим файлам;
   2. страж Stdlib Only / No Network In Core: `grep -nE '^[[:space:]]*(import|from)[[:space:]]+(urllib|http|socket|requests|yaml|numpy|pandas|Crypto|eth_|web3)' ethsc/evm.py`
      должен быть пуст, иначе `exit 1` с сообщением;
   3. **проба оркестратора** — inline-скрипт в приёмке, по одной проверке на каждый
      из 21 example компонента `evm`, плюс «ни одна функция не бросает» на трёх
      мусорных входах. Печатает `<Function> <N>: got …, want …` по каждому
      расхождению;
   4. `venv/bin/python -m pytest tests/test_evm.py -q --tb=short`;
   5. `venv/bin/python -m pytest tests -q --tb=short`.
2. **Карта судьи** (`tests/test_evm_examples.py`, по одному тесту на example, код не
   трогает): `ast.parse`, затем `pytest tests/test_evm_examples.py -q --tb=short`, затем
   `pytest tests -q --tb=short`.
3. Итог фазы: полный `venv/bin/python -m pytest -q --tb=short` зелёный, в нём не
   меньше 21 теста судьи.

Каждая приёмка обёрнута в снимок `/tmp/morph/<card>/` с логом `acc-<время>-<pid>.log`
и возвращает код своей цепочки. Обе цепочки прогнаны вручную в песочнице на
эталонной реализации: зелёные. Проба красная на мутации (регистр `target`), страж
красный на `import urllib.request`, отсутствующий модуль даёт красный `ast.parse`.

Тесты пишутся на `unittest`, у каждого assert есть `msg=`. В классах, которые
сравнивают списки или байты, стоит `maxDiff = None`: диагноз сравнения значений
должен дойти до регенерации целиком.

## 4. Ограничения

- Python 3.12 в рантайме, синтаксис совместим с 3.9, только стандартная библиотека.
- Новый файл: рамка правки существующего файла к нему не применяется.
- Один файл — одна карта-владелец. Судья пишет только свой тест.
- Модуль без ввода-вывода: не читает файлы, не печатает, не ходит в сеть.
- Tolerant Parser: на обрезанном, мусорном и пустом входе функции возвращают
  `[]`, `None`, `(code, b"")` и не бросают исключений.
- Во время рана дерево не трогается: правка файла из среза даёт `stale-context`.

## 7. Вне области

- компоненты `fingerprint`, `store`, `cluster`, `rpc`, `ingest`, `cli` и `ethsc/config.py` (фазы 2–5);
- sha256/`code_id`, похожесть, n-граммы (фаза 2);
- таблица имён опкодов, валидация JUMPDEST, CFG, декомпиляция;
- декодирование CBOR-метаданных (версия компилятора, IPFS/bzzr-хеш) — только отрезание;
- укороченные vanity-варианты EIP-1167 и другие прокси (EIP-1967, Safe, Diamond);
- селекторы вне dispatcher-шаблона «PUSH4 … EQ» и разметка селекторов по 4byte;
- `__main__.py`, CLI, любая сеть, новые фикстуры и правка существующих.

**Опровергаемое утверждение:** проба в приёмке `evm` точнее судьи. Код, прошедший
пробу, проходит все тесты `evm-judge` с первой попытки судьи. Если судья сгорит на
расхождении с example, значит, проба не покрыла это место, а разночтение сидит в
формулировке example.
