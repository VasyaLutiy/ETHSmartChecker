## 1. Зачем это

Сид сегодня смотрит только вперёд. `match_watchlist` вызывается ровно один раз на
адрес — в момент, когда адрес впервые записывается в базу (`ethsc/ingest.py:114–119`),
и только если `has_address` его ещё не знал (`ethsc/ingest.py:93–95`). Отсюда три
следствия, все три с числами.

- **Копии скама, уже лежащие в базе, не дают алерта никогда.** На фикстуре одного
  блока 26077729 — 206 адресов, 147 с кодом, 130 различных кодов. Сид на обычной паре
  UniswapV2 `0xb4e16d01…` даёт **4 алерта** (три копии того же кода с 1.0 и
  `0xcf6daab9…` с 0.8125), и сегодня их нельзя получить ни одной командой: `listen` и
  `backfill` эти адреса пропустят как известные, а `similar` печатает пары адресов, а
  не алерты вотчлиста. Один блок — 4 пропущенных алерта на один сид; база живого
  смоука — это тысячи блоков.
- **Алерты, потерянные прошлыми запусками, не восстанавливаются.** Долг явно оставлен
  в `docs/TASK_PHASE6_2.md` §7 двумя строками: окно между `put_address` и
  `match_watchlist` (`ethsc/ingest.py:114–119`) и «восстановления алертов, потерянных
  прошлыми запусками, нет и не будет в этой задаче». Фаза 6 задача 2 закрыла потерю
  алертов **завершённых** блоков (127 алертов за ~30 минут смоука перестали зависеть
  от момента Ctrl-C), но всё, что было потеряно **до** неё, так и лежит в базе немым:
  адрес записан, прогресс сдвинут, повторный проход его пропустит.
- **Порядок операций оператора решает, увидит ли он скам.** `seed add` сегодня — это
  запись одной строки в таблицу `seeds` (`ethsc/cli.py:192–199`), молча, с пустым
  stdout. Оператор, добавивший сид после суток приёма, не получает ни одного алерта по
  тому, что уже принято, и у него нет способа узнать, что он их не получил.

**База: 191 тест зелёный**, `pytest tests -q --tb=line` под блокировкой сокетов, 54 с,
29.09, дерево на `18da10f`. Ни один существующий тест новому контракту **не
противоречит**: `seed add` через `main` не вызывает ни один тест (сиды везде ставятся
напрямую через `Store.add_seed`), argparse-поверхность закреплена только проверкой
«нет подкоманды → 2», а `match_watchlist`, `find_similar` и `build_clusters` не
меняются вовсе.

## 2. Контракт

### 2.1. Формы ВХОДНЫХ данных (что придётся конструировать, и где это определено)

- **Seed** — `dict` ровно с ключами `address`, `label`, `code_id`; возвращает
  `store.seeds()` списком, отсортированным по `address`, адреса lowercase
  (`ethsc/store.py`, Function `Manage Watchlist` Контура). `add_seed(address, label)`
  поднимает `KeyError(address)` и на незнакомом адресе, и на адресе с `code_id` NULL.
- **Fingerprint** — `dict` ровно с ключами `code_id`, `size`, `skeleton_hash`,
  `selectors` (список), `proxy` (`{"kind", "target"}` или `None`); список даёт
  `store.fingerprints()`, отсортированный по `code_id`, одна запись на строку таблицы
  `codes` (`ethsc/store.py`, Function `Store Codes And Contracts`).
- **Alert** — `dict` ровно с ключами `address`, `seed_address`, `label`, `score`.
  Три ключа из четырёх строит `match_watchlist` (`ethsc/cluster.py:139–163`), ключ
  `address` сегодня дописывает `ingest_block` (`ethsc/ingest.py:116–128`); в Контуре —
  dataObject `Alert` группы `cluster`. **Второй формы алерта в проекте быть не
  должно.**
- **Публичный API Store**, и только он: `seeds()`, `fingerprints()`,
  `code_by_id(code_id) -> bytes | None`, `addresses_of(code_id) -> отсортированный
  список`, `code_of(address) -> bytes | None`, `add_seed(address, label)`.
  `store._conn` и любой другой приватный атрибут запрещены (страж §3.1 ходит по `ast`).
- **`similarity(a, b) -> float`** — `ethsc/fingerprint.py`, симметрична, не округляет,
  на мусоре и на `b""` не поднимает исключений.
- **Поверхность argparse** — `ethsc/cli.py:208–243`: глобальный `--db` до подкоманды,
  `sub = parser.add_subparsers(dest="command")`, у групповых команд второй уровень
  `dest="subcommand"`. Новая подкоманда встраивается в эту же конструкцию.
- **Печать алерта** — `_print_alerts(alerts)` (`ethsc/cli.py:63–75`): формат строки,
  `%.4f` и флаш stdout уже написаны там. Использовать её, а не заводить вторую печать.
- **Тестовые стабы** — `tests/helpers.py`: `temp_store()`, `block_codes()`,
  `block_receipts()`, `load_hex(name)`, `FakeRpc`, `FakeTransport`, `InterruptAfter`.
  Новых стабов задача не требует, **и файл не меняется**. Файлы `tests/test_cluster.py`
  и `tests/test_cluster_examples.py` живут на собственных локальных загрузчиках
  (`load_code`, `_block_store`, `_read_hex`) — **миграция их на `tests.helpers`
  запрещена**, как и в фазе 6: это чужой файл целиком, и она красит существующие тесты.
- **Фикстуры**: `codes_26077729.json` (206 адресов, 59 из них `"0x"`),
  `code_belle.hex`, `code_belle_copy_1807090d.hex`, `…_2141be5f`, `…_46cadea5`,
  `…_6411bed8`, `code_weth9.hex`, `code_clone_270df012.hex`.

### 2.2. Формы ВЫХОДНЫХ данных

- **`recheck_watchlist(store, min_score=0.8, seed_addresses=None)`** →
  `list[dict]`, каждый — `Alert` ровно с четырьмя ключами `address`, `seed_address`,
  `label`, `score`. `address` — сопоставившийся адрес базы, lowercase; `score` — float
  из `similarity`, **без округления**; `seed_address` и `label` — из `store.seeds()`.
  Порядок: `address` по возрастанию, затем `score` по убыванию, затем `seed_address`
  по возрастанию. Пустой результат — `[]`, не `None`.
- **Строка `ALERT`** — байт в байт та же, что у `listen` и `backfill`:
  `"ALERT\t<address>\t<seed_address>\t<label>\t%.4f\n"`. Второй печати алерта в
  `ethsc/cli.py` быть не должно — обе новые точки вывода идут через существующую
  `_print_alerts`.
- **`recheck`**: stdout — только строки `ALERT` в порядке, который вернула
  `recheck_watchlist`; stderr пуст; код возврата 0, в том числе когда алертов нет,
  сидов нет или база пуста.
- **`seed add`**: при успехе код 0 и строки `ALERT` по одному только что добавленному
  сиду (порог фиксированный 0.8, флага `--min` у неё нет); при `KeyError` — код 2,
  stdout **пуст**, stderr — прежняя одна строка `unknown address or no code: <addr>`.
- Коды возврата, строка остановки, форматы `clusters top`, `cluster`, `similar`,
  `seed list` — без изменений.

### 2.3. Имена

- `ethsc/cluster.py`: `recheck_watchlist(store, min_score=0.8, seed_addresses=None)`.
  Никаких других новых публичных имён в модуле.
- `ethsc/cli.py`: подкоманда `recheck` с единственным флагом `--min` (`type=float`,
  `default=0.8`); обработчик по идиоме файла — `_run_recheck(args, store)`; печать —
  существующая `_print_alerts`.

  Контура — `tests/test_cluster_examples.py`, `tests/test_cli_examples.py`. Новых

- Метки и адреса примеров: сид `0xb4e16d0168e52d35cacd2c6185b44281ec28c9dc` с меткой

### 2.4. Что не должно сломаться

- 191 существующий тест — зелёный, ни один не переписан.
- `build_clusters`, `find_similar`, `match_watchlist` — поведение и сигнатуры байт в
  байт; `recheck_watchlist` не заменяет `match_watchlist` и не меняет её.
- `ethsc/ingest.py` и его поток алертов: один алерт — одна строка, печать по
  завершении блока через `on_alerts`, алерт незавершённого блока печатается до строки

## 3. Приёмка

База: **191 тест**. `pytest` идёт через обёртку фаз 4–6, подменяющую
`socket.getaddrinfo` / `socket.socket.connect` / `socket.create_connection` на
`OSError("network blocked")`, с `INFURA_API_KEY=TESTKEY-ENV-0000` в окружении. Везде
`-q --tb=line`. «Проба оркестратора» — скрипт в самой приёмке, печатающий
`<сценарий>: got …, want …` по каждому расхождению и кончающийся ненулевым кодом; он, а
не тесты исполнителя, судит полноту. Все числа ниже измерены зондом на фикстурах
29.09 до написания карт.

## 4. Ограничения

- Python 3.12 в рантайме, синтаксис совместим с 3.9, только стандартная библиотека.
- Конверты правок: `ethsc/cluster.py` ~30–55 строк **без единого удаления** (новая
  функция дописывается, существующие не трогаются); `ethsc/cli.py` ~25–45 строк
  (парсер, `_run_recheck`, три строки в `_run_seed_add`, докстринг модуля). Не
  влезает — резать карту, а не расширять срез.
- Один файл — один владелец в поколении. `ethsc/cluster.py` пишется в первом
  поколении, `ethsc/cli.py` — во втором, вместе с судьёй `cluster`.
- Карта `cli` читает новую сигнатуру `recheck_watchlist`, поэтому идёт после
  `cluster`; судья `cli` — после `cli`.
- **Миграция `tests/test_cluster*.py` на `tests.helpers` запрещена**: файлы фазы 3
  живут на собственных загрузчиках, механическая замена красит 27 существующих тестов.
- Собственные тесты кодовых карт — смоук, не полнота: сравнивают скаляры и короткие
  значения (код возврата, длину списка, один адрес, один `score`), не целые списки и
  не словари размером с фикстуру; `maxDiff` не нужен. Полноту судят проба из §3 и
  карты судей.
- `KeyboardInterrupt` ловится по имени; голый `except:` и `except BaseException`
  запрещены — они проглотили бы `SystemExit`.
- No Network In Core, Secret Hygiene, Deterministic Output, Tolerant Parser — как в
  фазах 3–6.
- Правка файла во время рана даёт соседям `stale-context`; дерево во время рана не
  трогается.

## 7. Вне области

- **Хранение алертов в базе и отсев повторов между запусками.** `recheck` печатает
  одни и те же строки на каждом запуске — это и есть требуемый детерминизм. Таблицы
  `alerts` в этой задаче нет.
- **Окно между `put_address` и `match_watchlist`** (`ethsc/ingest.py:114–119`).
  Перепроверка его последствия лечит, само окно остаётся; `ethsc/ingest.py` не
  меняется.
- **Скорость `similar` и `recheck`** (MinHash/LSH), долг Контура 4 из §13 фазы 5. На
  базе в сотни тысяч кодов полный перебор «коды × сиды» станет больно — задача этого
  не решает, только не даёт стать хуже (P8).
- **`main()` строит `RpcClient(infura_url())` до разбора подкоманды.** Без
  `INFURA_API_KEY` `recheck` упадёт `RpcError` наружу из `main` — ровно как сегодня
  падают `similar`, `cluster` и `seed list`. Ленивое построение rpc починило бы все
  четыре сразу, но это правка поведения существующих подкоманд; названо вслух и
  оставлено.
- **Сид на прокси-адресе превращает перепроверку в шум.** У прокси (`eip1167`,
  `eip7702`) пустой список селекторов, поэтому `similarity` между любыми двумя прокси
  равна 1.0: сид `0x270df012…` даёт на фикстуре 8 алертов 1.0 на прокси с **другими**
  таргетами (сценарий P4 закрепляет это как факт, а не как желаемое). Это поведение
  `similarity`/`match_watchlist` из фазы 2, `ingest` ведёт себя так же. Порог по
  размеру кода или отдельная ветка для прокси — отдельная задача.
- Отбор адресов для перепроверки (по блоку, по дате, по кластеру), флаги `--since`,
  `--limit`, прогресс-индикатор.
- Живой смоук на Infura: офлайн-приёмка сети не касается вовсе.

## 9. Пререгистрация

| величина | прогноз |
|---|---|
| карт в колоде | 4 (`cluster`, `cluster-judge`, `cli`, `cli-judge`) |
| поколений | 3 (`cluster` → {`cluster-judge`, `cli`} → `cli-judge`) |
| счёт исполнителя | $0.03–0.12 |
| карт с регенерацией | 1–2 |
| тестов после | 200–210 |

**Опровергаемое утверждение:** ни одна карта не сгорит окончательно, а первой
регенерации потребует `cluster` — на сценарии P8 (соблазн написать цикл по адресам,
а не по кодам, потому что так короче) либо на порядке сортировки (по `score`, как у
`match_watchlist` и `find_similar`, вместо нового «по адресу»). Карта `cli` при этом
пройдёт с первой попытки: её правка механическая.
