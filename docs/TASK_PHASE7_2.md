## 1. Зачем это

База сегодня читается только построчно. `clusters top` печатает 20 строк

  таблица из восьми строк: 4419 кодов, 22 540 адресов, 333 блока, ledger

  на новой базе значит повторить ту же ручную работу.

  «Уникальных L1-скелетов < 30 %» против факта 75,7 % по `code_id` и 54,6 % с
  весом по адресам (3037 из 4014 непрокси-кодов). Эти три числа посчитаны один
  раз, скриптом, которого нет в дереве; на фикстуре одного блока их сегодня

## 2. Контракт

### 2.1. Формы ВХОДНЫХ данных (что придётся конструировать, и где это определено)

- **Fingerprint** — `dict` ровно с ключами `code_id`, `size`, `skeleton_hash`,
  `selectors` (список строк), `proxy` (`{"kind", "target"}` или `None`). Список
  даёт `store.fingerprints()`, отсортированный по `code_id`, одна запись на
  строку таблицы `codes` (`ethsc/store.py:131`, Function
  `Store Codes And Contracts`). На фикстуре `codes_26077729.json` — 130 записей,
  12 из них с `proxy` не `None`.
- **Cluster** — `dict` ровно с ключами `level` (`"L0" | "L1" | "proxy"`), `key`,
  `members` (отсортированные lowercase-адреса). Список даёт
  `build_clusters(store)` (`ethsc/cluster.py:22`), отсортированный по числу
  членов по убыванию, затем по уровню, затем по ключу. На фикстуре — 15
  кластеров: 7 L0, 2 L1, 6 proxy.
- **Alert** — `dict` ровно с ключами `address`, `seed_address`, `label`,
  `score`. Список даёт `recheck_watchlist(store, min_score=0.8,
  seed_addresses=None)` (`ethsc/cluster.py:166`), отсортированный по `address`,
  затем по `score` убыванию, затем по `seed_address`.
- **Seed** — `dict` ровно с ключами `address`, `label`, `code_id`;
  `store.seeds()` (`ethsc/store.py:208`), отсортирован по `address`.
- **Байткод** — `store.code_by_id(code_id)` даёт `bytes` или `None`;
  `disassemble(code)` (`ethsc/evm.py:11`) даёт список кортежей
  `(offset, opcode, immediate)`, и его длина — это число опкодов.
- **Счётчики базы** — `store.counts()` и `store.ledger_days()`: **их ещё нет**,
  их пишет карта `store` этой колоды, форма — §2.2 ниже и Function
  `Base Counts` Контура.

### 2.2. Формы ВЫХОДНЫХ данных (Контур не уточняет — уточняется здесь; в этих местах верен этот раздел, не `contour.yaml`)

**`Store.counts() -> dict`** ровно с пятью ключами, все значения `int`:

```python
{"addresses": 206, "addresses_with_code": 147, "addresses_without_code": 59,
 "codes": 130, "blocks": 1}
```

`blocks` — число **различных** значений `block` в таблице `addresses`, не их
размах. `addresses == addresses_with_code + addresses_without_code`. На пустой
базе все пять нули. Метод ничего не пишет и не коммитит.

**`Store.ledger_days() -> list`** — по одному `dict` на день, ровно с ключами
`day` (строка `"YYYY-MM-DD"`) и `credits` (`int`, сумма по всем методам дня),
отсортировано по `day` по возрастанию. На пустом ledger — `[]`.

**`collect(store) -> dict`** — ровно восемь ключей верхнего уровня:
`summary`, `levels`, `skeletons`, `clusters`, `codes`, `ledger`, `alerts`,
`spearman`. Только `int`, `float`, `str`, `None`, `list` и `dict`; ни пути, ни
даты, ни адреса объекта. Два вызова на одной базе дают равные структуры.

```python
"summary":  store.counts() дословно

"levels": {"L0":    {"clusters": 7, "addresses": 16, "share": 16 / 147},
           "L1":    {"clusters": 2, "addresses": 13, "share": 13 / 147},
           "proxy": {"clusters": 6, "addresses": 14, "share": 14 / 147},
           "proxy_codes": 12, "proxy_code_share": 12 / 130}
```

`addresses` уровня — число **различных** адресов во всех кластерах этого
уровня; `share` — это число, делённое на `summary["addresses_with_code"]`. Три
доли **не** дают в сумме единицу: один адрес может быть и в L0, и в L1. Любая
доля с нулевым знаменателем — ровно `0.0`, не `None` и не исключение.

```python
"skeletons": {"non_proxy_codes": 118, "unique_codes": 105,
              "unique_share": 105 / 118,
              "non_proxy_addresses": 127, "unique_addresses": 114,
              "unique_address_share": 114 / 127}
```

Только по непрокси-кодам. `unique_codes` — коды, чей `skeleton_hash` не
встречается ни у одного другого непрокси-кода. `unique_addresses` — сумма
`len(addresses_of(code_id))` по этим кодам; `non_proxy_addresses` — та же сумма
по всем непрокси-кодам.

```python
"clusters": {"top": [{"level": "L1", "key": "29ec9639b8…", "size": 8}, …],
             "histogram": {"edges": [2, 3, 4, 5, 9, 17, 33, 65],
                           "counts": [10, 2, 1, 2, 0, 0, 0, 0]}}
```

`top` — не более 20 кластеров, в том порядке, в котором их вернул
`build_clusters`; `size` — `len(members)`. `histogram` — по **всем** кластерам.

```python
"codes": {"size":      {"min": 20, "median": 4516, "max": 24313,
                        "histogram": {"edges": [0, 256, 1024, 4096, 8192,
                                                16384, 24576],
                                      "counts": [22, 5, 36, 19, 23, 25, 0]}},
          "selectors": {"min": 0, "median": 13, "max": 72,
                        "histogram": {"edges": [0, 1, 2, 4, 8, 16, 32, 64],
                                      "counts": [28, 2, 3, 16, 27, 35, 17, 2]}}}
```

Границы **фиксированы**, никогда не выводятся из данных: две базы должны
сравниваться. Значение попадает в последнюю корзину, чья граница его не
превосходит; последняя корзина открыта справа. `median` — ровно
`sorted(values)[len(values) // 2]`, нижняя медиана при чётном числе. На пустой
базе `min`, `median`, `max` равны `0`, а все счётчики нули.

```python
"ledger": {"days": store.ledger_days() дословно, "total": сумма credits}
"alerts": {"seeds": [{"address": …, "label": …, "count": …}, …], "total": …}
```

`alerts` — `recheck_watchlist(store)` (порог по умолчанию 0.8), свёрнутый по
`seed_address`: одна запись на сид, **у которого есть хотя бы один алерт**,
отсортировано по `address`; `count` — число алертов этого сида, `total` — длина
всего списка алертов.

```python
"spearman": {"features": ["bytecode_size", "opcode_count", "selector_count",
                          "address_count", "l1_family_size", "is_proxy"],
             "n": 130,
             "matrix": [[1.0, 0.9893…, …], …]}
```

Порядок признаков зафиксирован и одинаков для строк и столбцов. Значения —
`float` или `None`.

**Признаки одного кода**, по одной строке на строку таблицы `codes`:

| имя | чему равно |
|---|---|
| `bytecode_size` | `fingerprint["size"]` |
| `opcode_count` | `len(disassemble(store.code_by_id(code_id)))` |
| `selector_count` | `len(fingerprint["selectors"])` |
| `address_count` | `len(store.addresses_of(code_id))` |
| `l1_family_size` | число различных `code_id` с этим же `skeleton_hash` **по всем кодам базы, включая прокси** |
| `is_proxy` | `1`, если `fingerprint["proxy"]` не `None`, иначе `0` |

`l1_family_size` — **не** размер L1-кластера из `build_clusters`: там прокси
исключены, и прокси получал бы ноль, то есть столбец повторял бы `is_proxy`.
Здесь это свойство самого скелета.

**Одинаковые ранги.** Ранги — средние: значения сортируются, группе равных
значений присваивается среднее их позиций (1-based). Коэффициент — корреляция
Пирсона по этим рангам. Формула `1 − 6·Σd²/(n(n²−1))` **запрещена**: на
`[(1, 10), (2, 20), (2, 30), (3, 40)]` средние ранги первого признака —
`[1.0, 2.5, 2.5, 4.0]`, а коэффициент — `0.9486832980505138`.

**Вырожденные случаи.** Признак с нулевой дисперсией (все значения равны) даёт
`None` во всей своей строке и во всём своём столбце, **включая диагональ**;
остальные признаки сохраняют свои коэффициенты. При `n < 2` вся матрица —
`None`. Ни нулей вместо `None`, ни исключений.

**`spearman(rows) -> dict`** принимает список строк признаков в
зафиксированном порядке и возвращает `{"features", "n", "matrix"}`. Матрица
квадратная, симметричная, с `1.0` на диагонали (кроме вырожденных признаков).

**`render_html(data, svgs) -> str`** — одна страница. В ней **нет** `<script`,
`<link`, `<img` и ни одной подстроки `http`. Пять SVG вставлены дословно, у
каждого срезаны XML-декларация и DOCTYPE. На странице: сводка, доли уровней и
скелетов, верхние кластеры, ledger, алерты по сидам и матрица Спирмана —
таблицей рядом с тепловой картой. Каждый `float` печатается `"%.4f"`, каждая
`None`-клетка — пустой клеткой. Два вызова на одних данных дают равные строки.

**`build_report(store, prefix, charts=None) -> (html_path, json_path)`** пишет
`prefix + ".html"` и `prefix + ".json"` и возвращает их пути. JSON —
`json.dump(data, sort_keys=True, indent=2)` плюс завершающий перевод строки; ни
пути, ни даты, ни идентификатора внутри. При `charts=None` функция импортирует
`ethsc.charts` и на `ImportError` поднимает `ChartsUnavailable` (класс
определён в `ethsc/report.py`), **не написав ни одного файла**. Отображение
`charts` имеет ровно ключи `cluster_sizes`, `top_clusters`, `code_sizes`,
`selector_counts`, `spearman`; отсутствующий или лишний ключ — ошибка, а не
молча пропущенная картинка.

**`render_charts(data) -> dict`** в `ethsc/charts.py` — те же пять ключей, по
строке SVG в каждом. Модуль не считает ничего: все числа берутся из `data`.
Детерминизм покупается ровно тремя настройками: `matplotlib.use("Agg")` до
импорта `pyplot`, `rcParams["svg.hashsalt"]`, равный постоянной строке, и
`savefig(format="svg", metadata={"Date": None})`; каждая фигура закрывается.
Проверено 29.09 на matplotlib 3.11.2: два процесса с `PYTHONHASHSEED` 7 и 99
дают один и тот же sha256 `d6f53e0858cb92ac…`, в выводе нет ни `<dc:date>`, ни
`Created with matplotlib`. Побайтовое совпадение обещано внутри одного
окружения и одной версии matplotlib, не между версиями.

**Подкоманда `report [--out PREFIX]`**, `PREFIX` по умолчанию
`"ethsc-report"`. Пишет два файла, печатает ровно две строки в stdout — путь
html, затем путь json, — оставляет stderr пустым и возвращает 0, в том числе на
пустой базе. Без matplotlib: ни одного файла, пустой stdout, ровно одна строка
в stderr, называющая matplotlib, код 2, без трейсбека.

**Ленивый rpc.** `main()` строит `RpcClient(infura_url())` только на пути
`listen` и `backfill`. Для остальных подкоманд `infura_url()` не вызывается
вовсе, поэтому без `INFURA_API_KEY` и без `.env` они отрабатывают нормально, а
не трейсбеком. Параметр `rpc=` продолжает работать как раньше: переданный
объект используется, `None` означает «построй, если понадобится».

## 3. Приёмка

Каждая команда запускается из корня проекта интерпретатором `venv/bin/python`,
под блокировкой сокетов, с `INFURA_API_KEY=TESTKEY-ENV-0000` в окружении.
Полные цепочки — в `morph-map.json`; здесь — что именно они доказывают. Порядок
внутри каждой цепочки: свой разбор `ast` → guard → проба с числами → свой файл
тестов → весь набор.

### 3.1. Карта `store`

1. `ast.parse` для `ethsc/store.py` и `tests/test_store.py` с
   `feature_version=(3, 9)`.
2. Guard по `ast`: в `ethsc/store.py` нет импортов вне стандартной библиотеки,
   нет `urllib`, `http`, `socket`; ни один из прежних публичных методов не
   исчез; `counts` и `ledger_days` определены и не принимают аргументов кроме
   `self`; в `tests/test_store.py` не меньше шестнадцати функций `test_*`
   (шестнадцать существующих остаются) и не больше девятнадцати.
3. Проба: база из `codes_26077729.json` даёт
   `counts() == {"addresses": 206, "addresses_with_code": 147,
   "addresses_without_code": 59, "codes": 130, "blocks": 1}`; после
   `put_address` того же адреса в другом блоке `blocks` становится 2, а
   `addresses` не растёт; на пустой базе все пять нулей;
   `ledger_days()` на пустом ledger — `[]`, после
   `spend("2026-09-28", "eth_getBlockReceipts", 1000)`,

## 4. Ограничения

- Python 3.12 в `venv`, синтаксис 3.9-совместимый (это проверяет `ast.parse` с
  `feature_version=(3, 9)`).
- Стандартная библиотека везде, кроме `ethsc/charts.py`, где разрешён и нужен
  matplotlib. `numpy` приходит в `venv` как зависимость matplotlib — **это не
  разрешение его импортировать**: ни один модуль `ethsc/` не имеет права на
  `import numpy`, и guard это проверяет.
- Все числа считает `ethsc/report.py` стандартной библиотекой; `ethsc/charts.py`
  только рисует и не считает ничего.
- Файл, который пишет карта, не лежит в `context_slice` её соседей по
  поколению.
- Правка в дереве во время прогона даёт соседям `failed (stale-context)`:
  в дерево не лезть, читать — можно.
- Сеть запрещена в тестах и приёмках; сокеты блокируются в самой цепочке.
- Тесты самой кодовой карты — смоук: не больше пяти функций `test_*`, сравнение
  скаляров и коротких значений, никаких диффов на весь словарь `collect`.
  Полноту судит проба приёмки и карта `--judge`.

## 5–6. Техники и что намеренно не указано

Работало раньше и работает здесь: проба с парами «получено — ожидалось»,
копящая список `bad` и печатающая его целиком; guard по `ast`, а не по `grep`;
снимок целевых файлов в `/tmp/morph/<card>` первой командой цепочки.

Намеренно не указано: внутреннее устройство `collect` (один проход или
несколько), способ построения HTML (шаблон, `io.StringIO`, конкатенация),
оформление страницы, выбор цветов и размеров фигур, порядок разделов на
странице, имена приватных функций.

## 7. Вне области

- Интерактивность, JavaScript, любые внешние ресурсы в HTML.
- Живое обновление отчёта, слежение за базой, любой сетевой вызов.
- L2-кластеризация как новый уровень (`plan.md` §6).
- Ускорение `find_similar` (MinHash, LSH): полный перебор остаётся.
- PNG, PDF и любой формат картинки, кроме встроенного SVG.
- Любая правка `ethsc/evm.py`, `ethsc/fingerprint.py`, `ethsc/ingest.py`,
  `ethsc/rpc.py`, `ethsc/cluster.py`.
- Изменение схемы SQLite и любых существующих методов `Store`.
- Установка matplotlib из кода или из приёмки: это отдельный шаг человека,
  сделанный до прогона.
- Побайтовое совпадение SVG между разными версиями matplotlib.
