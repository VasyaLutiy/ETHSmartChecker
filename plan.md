## Context

**Цель.** Проиндексировать байткод контрактов Ethereum и разбить его на кластеры по коду. Прицел на безопасность: по одному известному скам- или уязвимому контракту найти все его копии и почти-копии.

**Первая веха — пруф на бесплатном тарифе Infura** (ключ `INFURA_API_KEY` лежит в `.env` проекта, Free, 3M кредитов в сутки). Своя нода откладывается.

**Что проверено 2026-09-28:**
- `eth_blockNumber` и `eth_getBlockReceipts` на этом ключе работают;
- `trace_block` недоступен, поэтому контракты, созданные фабриками, ищем по адресам, которые эмитят логи;
- WSS не проверяли, листенер опрашивает сеть по HTTPS.

**Роли.**
- Я — инженер, код не пишу.
- Весь код пишет Морф через сессии агента-оркестратора, одна сессия на фазу, старт по Шаблону А.
- Джон апрувит каждый Гейт и в одиночку мержит ветки `morph/<run-id>`.

## 1. Что делает система в пруфе

1. **Слушает мейннет.** Опрашивает `eth_blockNumber` и на каждый новый блок делает один вызов `eth_getBlockReceipts`.
2. **Отбирает адреса-кандидаты:**
   - `contractAddress` прямых деплоев;
   - `to` транзакций;
   - `logs[].address`.
3. **Запрашивает код.** Для кандидатов, которых нет в базе, вызывает `eth_getCode`. Действуют жёсткий лимит вызовов на блок и суточный бюджет кредитов, по исчерпании бюджета — чистая остановка с сохранённым прогрессом.
4. **Хранит.** SQLite хранит:
   - таблицу байткодов по `code_id`, где `code_id` — sha256 байткода (keccak в stdlib нет, для кластеризации он не нужен);
   - таблицу адресов;
   - таблицу прогресса.
5. **Анализирует байткод:**
   - дизассемблирует;
   - вырезает CBOR-метаданные компилятора;
   - строит «скелет», где данные в `PUSH20` и `PUSH32` замаскированы;
   - извлекает 4-байтовые селекторы из dispatcher'а;
   - распознаёт прокси EIP-1167 вместе с адресом implementation.
6. **Кластеризует по трём уровням:**
   - **L0** — одинаковый `code_id`;
   - **L1** — одинаковый хэш скелета, а для EIP-1167 — одинаковый implementation;
   - **L2** — похожесть: коэффициент Жаккара по селекторам, а если селекторов нет — по n-граммам опкодов, с порогом.
7. **Watchlist для безопасности.** Помечаем известный код меткой (`seed add <addr> --label`). При приёме каждого нового кода сверяемся с watchlist и печатаем алерт, если совпадение ≥ порога.
8. **CLI** `python -m ethsc`: `listen`, `backfill --from --to`, `clusters top`, `cluster <addr>`, `similar <addr> [--min 0.8]`, `seed add|list`.

## 2. Технические рамки (попадут в Контур как Requirement и Guardrail)

**Requirement:**

| Имя | Суть |
|---|---|
| Stdlib Only | Python 3.12, только стандартная библиотека (`urllib`, `sqlite3`, `hashlib`, `json`, `unittest`/pytest для тестов). Сторонних runtime-зависимостей нет. |
| Offline Tests | Ни один тест не ходит в сеть. Все данные сети берутся из `tests/fixtures/`, это дословные ответы Infura. |
| Real Fixtures | Каждое число в examples взято из фикстуры или независимого источника: Etherscan ABI, опубликованные селекторы, известный адрес implementation. Числа не выдумываются. |

**Guardrail:**

| Имя | Суть |
|---|---|
| No Network In Core | Сеть импортирует только `ethsc/rpc.py`. Остальные модули получают fetcher или transport инъекцией. |
| Secret Hygiene | Ключ читается только из окружения или `.env`. Он не попадает в логи, исключения, URL в выводе, фикстуры, спеки, колоды и коммиты. `.env` лежит в `.gitignore`. |
| Budget Respected | Лимиты на блок и сутки никогда не превышаются. Цены методов в кредитах живут в конфиге, а не в коде. Джон сверяет их с дашбордом Infura. |
| Tolerant Parser | Обрезанный или мусорный байткод, пустой код и сбой одного адреса дают None или пропуск, а не исключение, которое роняет блок. |
| Deterministic Output | Все отчёты полностью упорядочены, выдача не зависит от порядка вставки. |

## 3. Компоненты Контура (groups) и порядок фаз

Пакет `ethsc/`, примерно один модуль на компонент. Точную раскладку по файлам делает оркестратор в `morph-map.json`.

| # | Component | Functions (черновик, уточняет оркестратор) | Сеть |
|---|---|---|---|
| 1 | `evm` | Disassemble, Strip Metadata, Extract Selectors, Detect Minimal Proxy, Build Skeleton | нет |
| 2 | `fingerprint` | Fingerprint Code (code_id, skeleton_hash, selectors, proxy_target), Similarity Score | нет |
| 3 | `store` | Store Codes/Contracts, Progress, Watchlist, Budget Ledger | нет |
| 4 | `cluster` | Build Clusters (L0/L1/proxy), Find Similar (L2), Match Watchlist | нет |
| 5 | `rpc` | RPC Client (урезанный JSON-RPC поверх инъецируемого transport, retry и backoff на 429/5xx, учёт кредитов) | **только здесь** |
| 6 | `ingest` | Discover Candidates, Ingest Block, Follow Chain (resume, бюджеты) | через rpc |
| 7 | `cli` | `listen`, `backfill`, `clusters`, `cluster`, `similar`, `seed` | через rpc |

**Контур в учредительной фазе описывает все 7 компонентов сразу:** пруф — это одна система. Колоды режутся по компонентам (`mrph plan --spec contour.yaml --component <name> --judge`). Следующие фазы Контур дополняют, а не пересоздают.

## 4. Фикстуры: источник истины для examples

Собираются в учредительной фазе через `curl` на Infura. Это данные, а не код. Кладутся в `tests/fixtures/`, ключ в файлы не попадает.

| Фикстура | Что проверяет | Источник истины для чисел |
|---|---|---|
| `code_weth9.hex` (`0xC02aaA39b223FE8D0A0e5C4F27eAD9083C756Cc2`) | селекторы, дизассемблер, метаданные | 11 опубликованных селекторов WETH9 (`0x06fdde03` name … `0xdd62ed3e` allowance) |
| `code_usdt.hex` (`0xdAC17F958D2ee523a2206206994597C13D831ec7`) | селекторы большого контракта | ABI с Etherscan |
| Две пары Uniswap V2 (например USDC/WETH `0xB4e1…C9Dc`, WETH/USDT `0x0d4a…1852`) | L0: код идентичен | один и тот же `code_id` |
| Два EIP-1167-клона одного implementation | Detect Minimal Proxy, кластер по proxy_target | адрес implementation из байт клона и Etherscan |
| Два токена одной фабрики с разными immutable | L1: скелет совпадает, L0 различается | побайтовый diff фикстур |
| Один реальный блок `receipts_<N>.json` плюс `eth_getCode` его кандидатов | Discover Candidates, Ingest Block | подсчёт по файлу |
| Ответы с ошибкой (429, пустой `0x`) | retry, Tolerant Parser | записанные ответы |
| **Сид для безопасности:** 1–2 байткода известных скамов или honeypot-токенов и их копии (если найдём публично подтверждённые) | watchlist и `similar` | публичный отчёт или метка Etherscan |

Если подтверждённого скам-образца не найдётся, watchlist демонстрируется на безобидном семействе, например клонах Uniswap V2. Решение принимает Джон на Гейте Контура.

## 6. Out of scope для пруфа (следующие вехи, в Контур не входят)

- Флаги риска: `SELFDESTRUCT`, `DELEGATECALL` на изменяемый адрес, mint и blacklist только для владельца, изменяемые комиссии.
- MinHash/LSH и DuckDB/Parquet для миллионов кодов. В пруфе L2 считается полным перебором по базе.
- Полный бэкфилл мейннета: выгрузка из Reth на арендованном сервере или BigQuery.
- WSS-подписка, `trace_*`, контракты, созданные фабриками и не эмитящие логи.
- Разметка кластеров по верифицированным исходникам (Sourcify, Etherscan) и 4byte-сигнатурам.
- Веб, API, бот.
- Keccak-`codeHash`: не нужен, пока не сверяемся с внешними индексами.

  - `grep`: ключа нет в дереве;

- **Критерий пруфа (фаза 5):**
  - после ~1 часа `listen` в базе ≥ 1000 контрактов и бюджет кредитов не превышен;
  - `clusters top` показывает крупнейшие кластеры L0/L1, клоны EIP-1167 собраны по implementation;
  - `similar <адрес пары Uniswap V2>` находит другие пары;
  - `seed add` на сид, затем `listen`: при появлении копии печатается алерт.
- **Фальсифицируемое предсказание:** доля уникальных L1-скелетов среди увиденных контрактов < 30% (клонов много). Записывается в спеку фазы 5 до смоука.
